# lighting-checker — فاحص مطابقة الإنارة من مخططات DWG/DXF

يقرأ مخطط الإنارة، ويستخرج الغرف ووحدات الإنارة، ويحسب الإضاءة لكل غرفة، ويقارنها بجدول متطلبات، ثم يخرج تقرير HTML (خرائط حرارية + حكم مطابق/غير مطابق + العجز) وملف JSON لنظامكم.

## التشغيل

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m lighting_checker samples/Limog_elec.dwg --config config/project_limog.json -o out/report.html --json out/report.json
.venv/bin/python -m pytest -q
```

قراءة الكود: قيم المتطلبات تُقرأ عند كل تشغيل من `codes/egyptian-code.pdf` (الكود المصري 308، ملحق م1 جدول م1، ص 343) باستعمال `pdftotext` من poppler (`brew install poppler` أو `apt install poppler-utils`). يربط `config/rules_egypt.json` كل نوع غرفة بصفّه في الجدول عبر `pdf_row`، وإن كُتبت قيمة يدوياً فيجب أن تطابق الـ PDF وإلا يتوقف التشغيل.

تحويل DWG: يُستعمل ODA File Converter إن وُجد، وإلا `dwg2dxf` من LibreDWG (`brew install libredwg`).
LibreDWG رخصته GPL: للنموذج الأولي فقط؛ في الإنتاج استعملوا ODA File Converter أو ODA Drawings SDK، أو اطلبوا DXF من المصمّم.

## الوحدات

| الملف | الوظيفة |
|---|---|
| `cad.py` | تحويل DWG→DXF، تحميل DXF، وحدات الرسم ($INSUNITS) |
| `parser.py` | اللوحات (Frame block + عنوان)، الغرف، وحدات الإنارة وربطها بالغرف |
| `photometry.py` | قارئ IES LM-63 و EULUMDAT، الاستيفاء I(C,γ)، توزيعات عامة عند غياب الملف |
| `calc.py` | طريقة اللومن، الحساب نقطةً نقطة على مستوى العمل، الانعكاسات (split-flux)، UGR (CIE 117)، الطوارئ (EN 1838) |
| `report.py` | تقرير HTML بالعربية |
| `codebook.py` | قراءة جداول المتطلبات من PDF الكود (الكود المصري 308، جدول م1) |
| `codes/` | ملفات الكودات المعتمدة (PDF) |
| `config/` | إعداد المشروع، كتالوج الوحدات، جدول المتطلبات — **كل القيم قابلة للتعديل** |

## مصادر حدود الغرف (بالأولوية)

1. `polyline` — polyline مغلقة على طبقة `A-ROOM` (الأدق؛ يُقترح فرضها في معيار التسليم).
2. `walls` — لا حدود مرسومة: تُرسَم الجدران نقطياً (raster)، ويُملأ الفراغ حول نص اسم الغرفة. الأبواب (block فيه قوس فتح) تُغلق الفتحات، والأثاث والأدوات الصحية تُستبعد. المساحات المفتوحة ذات الاسمين تُقسَم بأقرب اسم.
3. `seed` — غرفة بلا اسم (حمّام، ممر) تُكتشف من موضع وحدة إنارة؛ نوعها من `room_hint` في الكتالوج.
4. `fragments` — غرفة مقطّعة بخطوط داخلية تُجمَّع قِطَعها (تقريبي، ويُعلَّم في التقرير).

## معيار التسليم المقترح على المكاتب

| العنصر | الطبقة | التمثيل |
|---|---|---|
| حدود الغرفة | `A-ROOM` | polyline مغلقة |
| اسم/نوع الغرفة | `A-ROOM-TAG` | نص داخل الغرفة |
| ارتفاع السقف | `A-ROOM-TAG` | نص `H=3.0` |
| وحدة إنارة | `E-LITE` | block بخصائص `MODEL`, `WATT`, `LM`, `IES` |
| إنارة طوارئ | `E-LITE-EMER` | block |
| مسار الهروب | `E-EGRESS` | polyline |

## حدود الدقة الحالية

* الانعكاسات تقديرية (تدفق منقسم موزّع بانتظام) — للمقارنة مع DIALux يلزم Radiance أو radiosity.
* بلا ملفات IES/LDT تُفترض توزيعات عامة؛ أضيفوا المسارات في الكتالوج (`"ies": "photometry/xxx.ldt"`).
* UGR تقديري (أربعة مراقبين، Lb = E_indirect/π)؛ الالتزام الرسمي بجداول UGR من المصنّع.
* جدول المتطلبات: المشروع يقرأ `config/rules_egypt.json` — الكود المصري 308 (إصدار 2007)، ملحق م1 جدول م1، صف «المبانى السكنية»، مع رقم البند لكل قيمة. الكود لا يحدد للإنارة الداخلية انتظاماً ولا بهراً، فلا يُفحصان. ويُفحص البند 6-2/3 (د): d/h ≤ 1.5، حيث d أكبر مسافة بين وحدة سقفية أو معلّقة وأقرب وحدة لها، وh ارتفاع التعليق عن مستوى العمل (الوحدات الجدارية لا تدخل؛ غرفة بوحدة واحدة: لا ينطبق). المخزن والغسيل وغرفة المصعد ليس لها بند، فتؤخذ مؤقتاً من `rules_residential.json` وتُعلَّم «مؤقت». ملف الكود الأردني `rules_jordan.json` قالب فارغ ينتظر قيم الكودة.
* التحقق: اختبارات تحليلية بروح CIE 171:2006 (مصدر نقطي، قانون التربيع العكسي وجيب التمام)؛ المقارنة مع DIALux على مشروع حقيقي لم تُجرَ بعد.
